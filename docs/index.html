The decision

A care navigation team has a fixed number of nurses and a fixed number of hours. It cannot call every member, so each January it works from a list. Here the list is the of adult members the team ranks highest, which comes to calls across the test years.

The usual way to build the list is to sort members by what they cost last year and start from the top. It is a good rule. Expensive people tend to stay expensive, the number is easy to explain, and it needs no model. Anything more complicated has to beat it at the same capacity to be worth running.

What that rule cannot see is the member who was cheap last year and will not be this year. Finding those members is what rising risk means here. The model looks for them in the rest of the record (age, sex, conditions, medications, labs, visits), predicts who will land in the top of next year's cost using only what was recorded before January 1, and is judged on how many of those members it puts on the list. Who the extra members turn out to be matters as much as how many there are, so that question gets its own section.

      Cost is not the same as need

      The model predicts cost. People who have trouble getting care spend less at the same level of illness, so a cost model can rank them lower than their health warrants. Obermeyer and colleagues (Science, 2019) found this in a widely used commercial algorithm. The check below asks whether members with the same score carry the same number of chronic conditions in every group.

      Chronic conditions at the same score

      Average number of active chronic condition groups by score decile. Each panel highlights one group against the others. A line above the rest would mean that group is sicker at the same score.

      Limits

      • The patients are synthetic, and that makes the problem easier. Synthea builds each patient from rule-driven disease modules, so cost follows the recorded conditions more predictably than it does in real claims. Nobody here is a real person, and these results should not be expected to carry over to real claims data.
      • The headline gain is mostly one group.
      • It does not work equally well at every age.
      • The target is cost. Cost is a stand-in for need and a flawed one. A team that cares about avoidable admissions or unmanaged disease should predict those instead, and accept that they are harder to measure.
      • The model says who will be expensive, not who a call will help. Some high-cost members cannot be helped by outreach and some cheaper ones can. Finding out who benefits takes an experiment that holds some members out of outreach at random. This project does not have one, so nothing here estimates savings.
      • The race comparison says nothing about a real population. Race and ethnicity in this data are whatever the generator assigned. The audit shows the method and has to be rerun on real members.
      • Nothing here is clinically validated. It shows how the work would be done, and it is not a tool for making decisions about patients.

      Run it yourself

      Everything on this page is rebuilt from a fixed seed by these commands.

      git clone https://github.com/aha124/rising-risk
cd rising-risk
make setup       # virtual environment and dependencies
make data        # generate the synthetic patients (needs Java, about 16 minutes)
make warehouse   # dbt build and tests, export the modeling table
make train       # train, evaluate, write the reports and the JSON this page reads
make site        # serve this page on http://localhost:8080
